Frontend API changelog

A menu item is now one document shared across many menus. Stop treating “same product on two menus” as two records. Base path: /api/v1.

Breaking — admin / organizer item CRUD Shape-only — nested chips Unchanged — guest app + staff reads

What changed at a glance

Topic Previous Now FE action
Storage menu = one ObjectId. Create cloned one doc per menuIds entry. menu = array of ObjectIds. One _id for the product. One form, multi-select menus
Create response data was an array of clones data is one object Do not loop data
Details / list menu Single id or one populated object Always an array of populated menus + menuIds Bind edit multi-select to menuIds
List rows One row per clone One row per product Show multiple menu chips
Update menus Changing menus created/deleted clones Send menuIds to replace membership Full list, not a patch
Duplicate menu Cloned every item Same item _ids; new menu id appended Do not expect new item ids
Guest / staff GET No menu on items Still no menu / menuIds None
Edit form contract: load GET .../items/:id → put data.menuIds into the menus multi-select → save with PUT body { "menuIds": [...] }. Use data.menu[].title for labels.

Mental model

Previous
Zinger on Main Course  →  _id A  (menu: Main)
Zinger on Lunch        →  _id B  (menu: Lunch)   // clone
Edit A does not change B
Now
Zinger                 →  _id A
  menu / menuIds       →  [Main Course, Lunch]
Edit A updates price/title everywhere it is linked

Frontend checklist

  1. Create item: menus multi-select → menuIds[]. Treat 201 data as an object.
  2. Edit item: prefill from menuIds; submit menuIds.
  3. Item table: one row; chips from menu / menuIds.
  4. Stop create/update/delete of “the same item on another menu” as separate records.
  5. Import: send subCategory for first-time imports.
  6. If UI used item.menu.title on discounts/combos/loyalty, use item.menu[0].title or join titles.
  7. Guest app and staff list/details: no change.

1. Create menu item breaking

POST /admin/menu/items
POST /organizer/menu-management/items

Required: title, basePrice, menuIds (non-empty ObjectId array). Other fields unchanged.

Request

3. Update menu item breaking

PUT /admin/menu/items/:id
PUT /organizer/menu-management/items/:id

Request

Previous
{
  "title": "Zinger Burger",
  "basePrice": 21,
  "menu": "MENU_MAIN"
}
/* or menuIds that spawned extra clones */
Now — replace full membership
{
  "title": "Zinger Burger",
  "basePrice": 21,
  "menuIds": ["MENU_MAIN", "MENU_LUNCH"]
}
  • menuIds replaces the list (not add/remove patch).
  • Omit menuIds and menu to leave membership unchanged.
  • menuIds: [] unlinks from every menu (item remains; guest list hides it).
  • Legacy menu (string or array) still works; prefer menuIds.

Response 200

Same shape as details: menu[] + menuIds[].

{
  "message": "Menu item updated successfully",
  "data": {
    "_id": "ITEM_A",
    "title": "Zinger Burger",
    "basePrice": 21,
    "menu": [ { "_id": "MENU_MAIN", "title": "Main Course", "status": "active" } ],
    "menuIds": ["MENU_MAIN"]
  }
}

5. Items by menu id

GET /admin/menu/items/menu/:menuId

Same membership filter. Shared _ids, not clones. Each row still has menu[] and menuIds[] (may include other menus besides :menuId).

GET /admin/menu/items/bundles?companyOrganizer=

Still a list of { _id, title, price }. No menu on bundle rows.

GET /admin/menu/items/:id/delete-impact

Unchanged purpose. Cascade still keys off the single item _id.

6. Import presets add subCategory for new imports

POST /admin/menu/items/import

menu is still a single menu id. New: if those presets are new for the organizer, send subCategory (presets only have old category).

Previous
{
  "menu": "MENU_MAIN",
  "companyOrganizer": "ORGANIZER_ID",
  "presetItems": ["PRESET_1", "PRESET_2"]
}
/* created a new item even if already imported */
Now
{
  "menu": "MENU_MAIN",
  "companyOrganizer": "ORGANIZER_ID",
  "presetItems": ["PRESET_1", "PRESET_2"],
  "subCategory": "SUBCAT_ID"
}
  • Already imported by this organizer → relink existing _id ($addToSet). No clone. subCategory not required for relink.
  • Brand-new preset → one item with menu: [MENU_MAIN]. subCategory required.
  • Response 201 data is still an array of item docs (imported / relinked rows).

7. Duplicate menu behavior

POST /admin/menu/duplicate/:id

Request body is unchanged:

{
  "organization": "ORG_ID",
  "name": "Main Course copy"
}
Previous
New inactive menu
+ cloned every item (new _ids)
linked only to the copy
Now
New inactive menu
Items keep the same _ids
New menu id is appended to menu[]

GET item → menuIds includes source + copy
Do not expect a new item id per product. Deleting a duplicated menu does not currently remove that id from items; PUT menuIds to clean up if needed.
